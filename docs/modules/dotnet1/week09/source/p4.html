WEDNESDAY One Page, Two Widths: Media Queries

Know: Read a media query and say which rules apply at which widths, and why a query must not change the page text.

Value: Show concern for classmates whose only computer is a phone.

Do: Add two media queries to Juan's stylesheet and test them by making the browser window narrower.

Today's starting point: Juan's layout is the same at every width: on a narrow screen the nav bar is cramped and the cards waste the space beside them.
Media queries. @media (max-width: 900px) { ... } wraps rules in a condition: the browser uses them only while the page is 900 pixels wide or narrower, and re-reads the condition whenever the width changes. The width is the page's, not the screen's, so a narrower browser window turns a query on: the page window follows the browser window, and you cannot drag the page window itself. A query may change how boxes sit, never the words on the page: a step's expected output must be the same at every width.
ANALOGY A folding sari-sari store: open on a wide pavement it spreads its goods in a row; on a narrow one it stacks them. Same goods, same words on the price list, different arrangement.

STEP 5 · index.html, styles.css · run page: index.html

A media query gives a rule a condition. @media (max-width: 900px) { ... } means: use the rules inside only while the page is 900 pixels wide or narrower. Inside it, nav ul gets flex-direction: column, so on a narrow page the nav items stand one under the other and each one is easy to tap. Nothing outside the query changes. Run index.html unchanged.

styles.css · a new media query (end of the file)

/* Media query: on a page 900px wide or narrower, the nav items stand one under the other */
@media (max-width: 900px) {
  nav ul {
    flex-direction: column;
  }
}

Output (page text): the same as Step 4's output; flexbox and media queries move boxes, they do not rewrite the page text.

Check yourself: On a module step the page sits beside its checks, and that page is narrower than 900 pixels, so the query is already on: the nav items stand in a column. The output is the same as Step 4's, because each nav item already had its own line there. A media query moves boxes; it must never change the page text, or a step could never pass. Your task: page 10, Step 5.

STEP 6 · projects.html, contact.html, styles.css · run page: projects.html

A media query can also turn a column into a row. The same condition, max-width: 900px, gives .project-list flex-direction: row and flex-wrap: wrap, so on a narrow page the project cards sit side by side and wrap instead of using one long column. Two queries with the same condition may live in the same stylesheet. Run projects.html unchanged.

styles.css · a second media query (end of the file)

/* Media query: on a narrow page the project cards sit side by side and wrap, to use the width that is left */
@media (max-width: 900px) {
  .project-list {
    flex-direction: row;
    flex-wrap: wrap;
  }
}

Output (page text): only these lines differ from Step 2's output.

Practice: is the query on? On a module step the page beside the checks is narrower than 900 pixels. (a) @media (max-width: 900px); (b) @media (max-width: 600px); (c) @media (max-width: 900); (d) the same query after you make the browser window wider than 900 pixels. Answers: (a) on; (b) off: the window is wider than 600; (c) never: the length has no unit, so the query is dropped; (d) off.
