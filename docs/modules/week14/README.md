# Week 14 rolling practice example

The teacher approved this first example on 2026-10-20, on `codex/rolling-module-tasks`.

- `Java2_Week_14.codeshare.json`: eleven small alterations and verified task outputs. Same
  published module/lesson/step ids; separate task ids. Upload in the same class after the app
  change is deployed. Re-uploading replaces content; old passes do not complete new tasks.
- `Java_Collections_Framework_Module.pdf`: original eight pages plus three practice pages.
  Print pages 1-6 double-sided, long-edge; pages 7-8 single-sided for the original liplets.
  Pages 9-11 are the new practice appendix and may be printed separately. Every page is
  8.5 by 13 inches. Original sample code and outputs are retained, including demonstrations.
- `Java_ILAW_Week_14.docx`: original lesson plan plus one task-mapping appendix. The existing
  school grid, references, signatures and blank Reflections cells remain unchanged.

The PDF and lesson appendix use exactly the task instructions from the JSON. All eleven
reference alterations were run with real multi-file laptop Java. Step 1 uses a fixed friendly
message rather than platform-specific exception wording. Step 4 displays a sorted copy of the
HashSet. Step 8 lists empty vehicles without removal; Step 9 practices Iterator removal.

The preceding module id is `java-2-w13`; its JSON is not part of this stage. Existing prior work
is copied when available; absent work starts from the supplied Vehicle classes. Current student
files always win. To follow a later sample, students edit their saved Main.java themselves,
using the worksheet's full sample as a guide. New supporting classes are added when missing.
No solved task files are uploaded. The test-only reference edits are in
`tests/fixtures/week14-task-edits.json`.

The personal performance task remains separate. Running module practice never submits it.
The older generation prompt/playbook and the other five weeks await their own next-stage work.
File persistence and Swing execution were not added.
