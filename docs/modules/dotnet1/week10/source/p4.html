WEDNESDAY A Local Template, Then Your Own Rules

Know: Read a local template stylesheet and say which rule wins when it and your own rule are equally strong.

Value: Appreciate work others share, and the honesty of saying what came from a template.

Do: Link the template before styles.css, use its classes, then override it with your own rule.

Today's starting point: Juan wrote every rule himself; he has never used CSS somebody else prepared, or decided which rule wins.
Templates and which rule wins. A template is CSS somebody else prepared. In class it must be a file inside the project, never an address on the internet. A page may link two stylesheets; both apply, and when two rules are equally strong the later one wins. Keep the template file unchanged; write your own rules in your own stylesheet.

STEP 5 · projects.html, contact.html, resume-template.css, styles.css · run page: projects.html

A template is ready-made CSS you may use. resume-template.css is a small one kept in the project: read it, it is plain CSS, and nothing is loaded from the internet. projects.html links the template first and styles.css second; the list takes class="project-list t-grid" and each card class="t-card", so the template gives the columns, the 16px gap and the border. Run projects.html unchanged.

resume-template.css · the rule this step uses (the whole file is on page 13)

.t-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: 16px;
}

projects.html · the two stylesheet lines, the template first

  <link rel="stylesheet" href="resume-template.css">
  <link rel="stylesheet" href="styles.css">

projects.html · the list and its cards take the template's classes

  <ul class="project-list t-grid">
    <li class="t-card">Science poster: Saving water at home <span class="badge">solo work</span></li>

styles.css · .project-list keeps only what the template does not do

/* The template's .t-grid lays the cards out; this keeps the rest */
.project-list {
  list-style-type: none;
  padding-left: 0;
}

Output (page text): the same as Step 2's output; a grid moves boxes and a resized picture has no words, so the page text does not change.

Check yourself: The output does not change: a template moves boxes and draws borders. The checks now find the template's 16px gap, and each card has a light border. Your task: page 10, Step 5.

STEP 6 · projects.html, contact.html, resume-template.css, styles.css · run page: projects.html

Your own CSS beats a template you keep. Juan writes his own columns, minmax(260px, 1fr), and gap: 12px in styles.css. Both are plain class selectors, so the later one wins: styles.css is linked after the template, which still draws the card borders. The template file itself is never edited. Run projects.html unchanged.

styles.css · Juan's own rule takes the columns and the gap back

/* My own rule wins: styles.css is linked after the template */
.project-list {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(260px, 1fr));
  gap: 12px;
  list-style-type: none;
  padding-left: 0;
}

Output (page text): the same as Step 5's output; a grid moves boxes and a resized picture has no words, so the page text does not change.

Check yourself: The output is the same as Step 5's. The checks now read a 12px gap instead of the template's 16px: the proof that Juan's own rule won. Your task: page 10, Step 6.

Practice: which rule wins? The template is linked first, styles.css second. (a) the template's gap: 16px against your gap: 12px; (b) .t-card's border, which styles.css never mentions; (c) the same rule written twice in styles.css. Answers: (a) your 12px, equal strength and later file; (b) the template's; (c) the second one. Never edit the template file itself.
